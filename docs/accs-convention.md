# 악세사리 설계·이름·설명 규칙

이 저장소의 악세사리는 전부 이 규칙으로 만든다. 표기와 설명 문장은 [나무위키 겟앰프드 악세 문서](https://namu.wiki/w/%EC%9A%B0%EC%A3%BC%ED%98%95%EC%82%AC(%EA%B2%9F%EC%95%B0%ED%94%84%EB%93%9C)) 형식(기본 정보 → 능력치 → 입력별 기술 목록 → 한 문장 설명)을 따른다. 포맷·명령어 같은 기술 규칙은 [modding-rules.md](modding-rules.md)에 있고, 이 문서는 **무엇을 어떤 슬롯에 넣고 어떻게 부를지**만 다룬다.

## 1. 입력 표기

나무위키 표기를 그대로 쓴다. `D` 대시 중, `V` 점프 중, `Z` 조준(Z 유지). 화살표는 연계.

| 표기 | 뜻 | poa 기술 이름 | 상태 비트 |
|---|---|---|---|
| `C` / `C→C` / `C→C→C` | 서서 약공격 1·2·3타 | `W_s` `W_ss` `W_sss` | `SW` / 연계 |
| `X` / `X→X` | 서서 강공격 1·2타 | `W_b` `W_bb` | `SW` / 연계 |
| `D+C` / `D+X` | 대시 약 / 강 | `D_s` `D_b` | `R` |
| `V+C` / `V+X` | 점프 약 / 강 | `J_s` `J_b` | `F` |
| `Z+C` / `Z+X` | 조준 약 / 강 | `A_s` `A_b` | `A` |
| `Z+XC` | 지상 필살기 | `A_x` | `A` |
| `V+XC` | 점프 필살기 | `J_x` | `F` |
| `D+XC` | 대시 필살기 | `D_x` | `R` |

원본 격투가 poa에는 `J_x`·`D_x`가 없다. 악세 poa에서 새로 추가한다. `W_s`·`W_b`는 원본 상태가 `SWA`라 조준 중에도 먼저 잡히므로 **`SW`로 줄여야** `Z+C`·`Z+X`가 나간다.

## 2. 슬롯별 역할

| 슬롯 | 역할 | 지침 |
|---|---|---|
| 기본공격 `C` `X` | 원본과 거의 같은 기본 공격 | 원본 모션·연계 유지. 테마 이펙트와 피격 반응(화상·빙결 등)만 바꾼다. 위력은 원본 ±2. 광역·발사체 금지 |
| 점프공격 `V+C` `V+X` | 약속: `V+X` 발 공격, `V+C` 팔꿈치 | `V+C`는 원본 그대로 둔다(바꾸지 않는 관례). `V+X`만 테마 킥으로 교체 |
| 조준공격 `Z+C` `Z+X` | 악세의 개성. 특수효과·원거리 | 발사체·레이저·설치형 등 "이 악세만의 기술". 위력은 성능에 따라 10~26 |
| 필살기 `Z+XC` `V+XC` `D+XC` | 상황별 고성능 | `Z+XC` 지상 광역·확정타, `V+XC` 공중에서 떨어지며 범위 타격, `D+XC` 추격·돌진형. 필살기만 `ignoreAttack` 허용. 위력 합계 20~30 |

대시 기본공격 `D+C`·`D+X`는 기본공격에 준한다. 대시형 발사체는 `Z+C`로 옮긴다.

## 3. 이름 규칙

- **악세 이름**: 한글 2~3어절, `테마 + 장비` (예: 헤비 글러브, 볼케이노 건틀릿, 얼음 장갑). 파일 id는 소문자 영어 한 단어(`heavygloves`).
- **기술 이름**: 한글 2~4어절, `테마어 + 동작` (예: 얼음 잽, 글러브 태클, 빅 레이저). 같은 악세 안에서 테마어를 통일한다(얼음·빙결·서리처럼 계열어는 허용).
- **스크립트 파일**: 소문자 영어, 기술 이름의 직역(`icejab.sc`, `glovetackle.sc`). 타격 이름도 같은 어근을 쓴다.
- 필살기 이름은 기본기와 구분되게 2어절 이상으로 길게 짓는다(기가 임팩트, 프로스트 노바).

## 4. 설명 규칙

- **악세 소개**: 1~2문장. 1문장째 외형, 2문장째 플레이 느낌(무엇이 강하고 무엇이 약한지).
- **기술 설명**: 한 문장, `~하는 기술입니다.`로 끝낸다. 순서는 **동작 → 연계·범위 → 특수효과**.
  - 예: "비트를 앞세워 2번 공격한 뒤 폭발시켜 띄우는 기술입니다."
  - 예: "전방 3방향으로 레이저 빔을 발사하는 원거리 기술입니다."
- 수치는 설명에 쓰지 않는다(위력은 모아보기 카드에 안 보이고, 바뀌면 문장이 틀어진다). 가드 무시·무적·빙결 같은 **상태**만 쓴다.

## 5. 스펙 파일에 적는 법

`mods/accs/<id>.txt` 맨 위 주석 블록이 모아보기 카드의 데이터다. 빌드(`tools/gen_accs_catalog.py`)가 읽어 `web/accs.json`을 만든다. **기술 줄은 기록용**이다. 카드에는 이름·소개·능력치만 나오고 기술 목록은 공개하지 않는다(어느 입력에 뭐가 나가는지 찾아보는 재미를 남기기 위해).

```
# 얼음 장갑 — 양손 파란 글러브. 맞은 상대가 얼어붙어 연속 공격에 강하다.
# tech C      얼음 잽      — 잽을 날려 맞은 상대를 잠시 얼리는 기술입니다.
# tech Z+X    빙결 레이저  — 전방으로 가드를 무시하는 냉기 레이저를 발사하는 기술입니다.
# tech Z+XC   프로스트 노바 — 뛰어오르며 사방에 냉파를 터뜨려 주위를 모두 얼리는 기술입니다.
```

- 1줄: `# 이름 — 소개`.
- `# tech <입력> <기술 이름> — <설명>`: 입력은 1절 표기 그대로. 순서는 기본 → 대시 → 점프 → 조준 → 필살기. 교체하지 않은 슬롯(원본 유지)은 적지 않는다.
- 다른 `#` 줄은 메모로 취급해 카드에 안 나온다.

## 6. 필살기 설계 규칙

세 필살기는 전부 아래 골격을 따른다. 기본기와 확실히 달라 보여야 한다.

| 단계 | 내용 | 시간 |
|---|---|---|
| 예고 | `stop()` + 충전 이펙트(`lcharge.oa` `fcharge.ptc` `cold.ptc`) + `ignoreAttack(총 길이)` + **`bind(총 길이)`**(입력 잠금: 공중에서 XC 를 또 누르면 점프 필살기가 겹쳐 발동하는 것을 막는다) | 0~500ms |
| 발동 | 큰 이펙트 2~4개 + 효과음 `play("/sound/5.sr",100,1)`(폭발) / `7.sr`(얼음) + 타격 | 500~900ms |
| 여운 | 잔상 이펙트 1개, 회복 `recover()` | ~1500ms |

- **`Z+XC` 지상**: **제자리에서 손만 휘두르는 필살기는 금지.** 반드시 움직임이나 발사가 있어야 한다. 유형은 여러 가지이고 악세마다 다르게 고른다(같은 유형이 둘이면 하나를 바꾼다):
  - 쏘기: 전용 발사체·레이저를 여러 발(`biglaser.aoa`, 전용 aoa 부채꼴).
  - 도약 후 내려찍기: `landScript("착지.sc")` 등록 → `move(0,1.6)`+`jump(11.0)` 로 앞으로 솟구침 → `move(0,-11,0.4)` 급강하. 폭발·타격은 **착지 스크립트 안에서**(시간으로 맞추면 헛친다). 8방향 타격 반경 1.1, `y -0.3`. 예: 볼케이노 크래시.
  - 물건 날리기: 수류탄·포탄 계열 전용 aoa 를 연달아 던지기.
  - 회전: `turn(k*45)` + `move(0,2.2)` 를 170ms × 8 로 팔각형을 돌며 걸음마다 이펙트+타격, 마지막 중앙 대폭발. 예: 블리자드 스핀.
  - 돌진·왕복, 설치형(바닥에 남는 이펙트+지연 타격)도 가능.
  마무리 타격은 `pitch` 로 방향을 나누고 반경 0.7 이상 떨어뜨린다. 같은 지점에 겹치면 한 상대에게 전부 들어가 즉사한다.
- **`V+XC` 점프**: 첫 블록에서 `jump(3.5)` 로 한 번 더 띄운 뒤 발사체를 **3~5발 부채꼴**(`pitch 0/±25/±50`)로 뿌린다. 한 발로 끝내지 않는다.
- **`D+XC` 대시**: 돌진하며 다단 히트(1타 7~11) 후 마무리 한 방(`hit_B6`/`hit_explode`). 전진량은 `move(0,2.4~4.0)`.
- 발사체 필살기는 **전용 aoa** 를 만든다(§9).
- 착지 스크립트(`landScript`)에도 `bind(900)` 을 넣는다. 착지 직후 입력이 가드·다른 기술로 새는 것을 막는다.
- 타격 반경을 키우려면 `aoa attack_big.aoa attack_s2.aoa size=0.9` 로 판정 구를 키운 모델을 만들어 쓴다(원본 `attack_s1` 0.2, `attack_s2/s3` 0.3). 큰 판정은 방향이 겹치므로 4방향이면 충분하다. 원본 수류탄은 착탄 반경 0.5·위력 8 로 필살기감이 없다.

## 7. 위력·밸런스 규칙

- **`dhit_*.sc` 를 타격 `effect` 로 쓰지 않는다.** 이름과 달리 사망 연출(`die()`)이라 위력과 무관하게 즉사한다. 보통 타격은 `hit_*.sc` 만.
- **겹치는 다단 히트는 합산된다.** `attack` 여러 개를 같은 시각·같은 위치에 두면 한 상대가 전부 맞는다. 광역은 방향을 나누고, 연타는 시간을 150~250ms 띄운다.
- `hit_freeze.sc` 는 피격자에게 2.5초 무적을 건다. 빙결 계열은 다단 히트를 넣어도 첫 타만 들어가므로 1타 위력을 조금 높게(12~16) 잡는다. `hit_burn.sc` 는 이런 보호가 없다.
- 발사체의 `attack` 위력은 **몸체 명중**에만 쓰인다. 착탄 폭발은 aoa `end.sc` 의 `attackNow(x,y,z,반경,위력,피격sc,-1,false)` 가 따로 정한다.
- 필살기 위력 합계는 상대 체력의 절반을 넘기지 않는 선(합산 20~30)으로 잡고, 실제로 들어가 보고 두 방에 쓰러지는지 확인한다.

## 8. 이펙트 규칙

- **기술마다 눈에 보이는 이펙트 1개 이상.** 타격만 있고 연출이 없으면 "밋밋하다"는 평가가 나온다.
- 스스로 모양을 만드는 이펙트(스크립트에서 `makeShapeModel` 한 줄로 끝): `fire1 honoo explode1 explode2 crash spark jet quake shock tornado lcharge biglaser_fire kiai_red cold1 frzflush iceshot_hadou iceshot_clash flash`. 파티클은 `makeParticle("fcharge.ptc"|"cold.ptc"|"p1.ptc", x,y,z, 0,1,0)`.
- `hadoushot.oa` 처럼 `start.sc` 가 없는 `.oa` 는 띄워도 안 보인다. 새 이펙트를 쓰기 전에 `AoaDump` 로 `start.sc` 에 `setShape` 가 있는지 본다.
- **한 번에 띄우는 이펙트 수를 아낀다.** `explode1/2` 는 안에서 파티클을 또 만든다. 착탄 하나에 파티클 이펙트 1개 + 가벼운 것(`crash` `honoo` `cold1`) 2~3개. 발사체 5개 × 폭발 5개처럼 쌓으면 렌더러가 수 초간 예외를 뿜는다.
- 발사체(AttackModel) 안의 `attack.sc`/`end.sc` 에서는 부모를 전제하는 호출(`makeShapeModel` 의 8번째 hasparent 인자 등)을 쓰지 않는다. 원본 aoa 에 있는 명령만 쓴다: `setSize` `startAnimation` `attackNow` `makeShapeModel`(6인자) `invisible` `kill` `play` `checkMask`.
- 크기 체감: 발사체는 `attack.sc` 의 `setSize(1.8,1.8,1.8)`, 지상 광역은 반경 0.8~0.9 에 이펙트를 둘러 배치, 회오리(`tornado.oa`)·균열(`quake.oa`)은 바닥(`y -0.3~-0.4`)에.

## 9. 전용 발사체 만들기

poa 스펙에 한 줄:

```
aoa meteor.aoa ../../../web/game/resource/attack/hgrenade.aoa attack.sc meteor_fly.sc end.sc meteor_end.sc
attack meteor meteor.aoa hit_explode.sc 10 0.8 800 0.0 0.0 0.3 0.0
```

- `attack.sc`(비행 중): `setSize` + `startAnimation(105,106,105,5,1)` 정도만.
- `end.sc`(착탄): `-1:` 블록에 `attackNow(0,0,0,1.5,18,"hit_explode.sc",-1,false)` + 효과음 + `checkMask(0)`, `0:` 블록에 이펙트와 `invisible()`, `800:` 에 `kill()`.
- 바탕으로 쓸 수 있는 것: `hgrenade.aoa`(포물선), `bombshell.aoa`(포물선, 로켓 모델), `fireshot.aoa`/`iceshot.aoa`(직선), `biglaser.aoa`(가드 무시 레이저), `hadou.aoa`(직선 파동).
- 추적 발사체의 바탕은 **직선형(`fireshot.aoa`/`iceshot.aoa`)** 을 쓴다. 포물선형(`bombshell`·`hgrenade`)은 위로 떴다 떨어지는 궤적이라 유도를 붙여도 "적에게 날아간다"는 느낌이 안 난다. 몸체는 `setSize` 2 이상 + 100~120ms 간격 꼬리 이펙트가 있어야 눈에 띈다(드론 컨트롤러 실측).
- **적을 쫓아가는 발사체는 `homing=<초당 이동량>` 옵션으로 만든다**(예: `aoa drone.aoa ../../../web/game/resource/attack/bombshell.aoa homing=4.5 ...`). 원본 엔진에는 추적이 없다. aoa 의 `correctvec` 은 "발사 순간 조준 대상 쪽으로 방향 보정"일 뿐 날아가는 동안 꺾이지 않는다. 추적은 이 저장소가 `AttackModel` 을 오버라이드해 넣은 기능이고, 가장 가까운 살아 있는 적(NPC 포함)을 매 프레임 쫓는다. 속도 9 에 `attack` 의 `time` 1500 이 기준이다. 발사체는 `time` 이 끝나면 그 자리에서 터지므로 유도 발사체는 비행시간을 넉넉히(1200~1500ms) 주고 속도도 빠르게(8~10) 해야 목표에 닿는다. 4.5/800ms 로는 2~3 앞에서 터졌다.
- `fireshot.aoa`/`iceshot.aoa` 는 모델이 없고 `attack.sc` 의 `setShape("fireball2.shp")` 가 그린다. `attack.sc` 를 바꿀 때 그 줄을 빼면 안 보인다. 원본 `attack.sc` 의 `650: kill()` 은 원본 비행시간(400ms)용이라 **비행시간을 늘렸으면 빼야** 몸체가 중간에 사라지지 않는다. `bombshell.aoa` 는 로켓 모델이 있어 `setSize` 만 하면 되는데 2.5 이상은 줘야 눈에 띈다.
- 비행 중 꼬리: `attack.sc` 에 120ms 간격 시간 블록으로 `makeShapeModel("/effect/spark.oa",0,0,0,0,0,1)` 을 남기면 지나간 자리에 흔적이 찍혀 궤적이 보인다(파티클 없는 이펙트만).
- 한 기술에서 여러 발을 쏠 때는 120~200ms 시간차를 둔다. 유도 발사체라도 한 점에 겹치지 않고 연달아 착탄한다.

## 10. 검증 체크리스트

`node tools/verify_accs.mjs <id>`(헤드리스, modding-rules §4)로 돌리면 1~5번이 한 번에 나온다. 손으로 볼 때는 `?accs=<id>&debug=1`.

1. 14슬롯 전부 `[tech]` 로그가 찍히는가(`J_x` `D_x` 포함).
2. 콘솔에 `Exception` 이 새로 늘지 않는가(원래 나오는 `dic_en` `lpoint` `ThrowItemAction` 은 무시).
3. 필살기를 맞은 상대가 **한 방에 죽지 않는가**.
4. 필살기마다 이펙트가 눈에 보이는가(스크린샷).
5. 발사체는 착탄까지 기다려 본다(튕김은 착탄 순간에 난다).

## 11. 위력 가늠표

원본 격투가 기준(잽 4, 훅 5, 스트레이트 7~8, 대시킥 9, 어퍼 10). `str`은 밀어내는 힘(0.4 잽 ~ 0.9 강타).

| 슬롯 | 위력(합계) | 피격 반응 |
|---|---|---|
| 기본 1타 | 4~8 | `hit_B1`~`hit_B3`, 테마형(`hit_burn` `hit_freeze`) |
| 기본 마무리·대시 | 9~13 | `hit_B4`(띄움) `hit_B5`(날림) + `kickback1.sc` 피드백 |
| 조준 | 10~26 | 발사체는 aoa 비행시간에 맞춘 `time`(fireshot 400, biglaser 800, hgrenade 800) |
| 필살기 | 20~30 | `hit_B6` `hit_explode`(크게 날림), 다단히트는 1타 8~12 |
